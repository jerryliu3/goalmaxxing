# Linked goals: completion credit without planning suppression

## Product contract

A link means completing the source goal also counts toward the target goal on that date, subject to the existing ownership, lifetime, and cascade rules. Both goals remain ordinary goals: independently discoverable, directly completable, and independently schedulable.

Links no longer hide targets from the checklist or calendar, delay their placement until a source ends, prohibit moving them onto source-active dates, or reserve target work based on planned source sessions. A planned source session is not a completion. Only canonical completion facts reduce remaining target work.

The goal editor calls the relationship “Also counts toward”; session details expose direct links to the target goals. There is no hidden-linked-goals filter, return date, or suppression explanation.

## Implementation boundary

Remove suppression and projected source coverage from preparation, preview, and save together. Keep completion reconciliation, durable planner unit keys, completion cascades, ownership validation, and exact-date completion writes intact. Link summaries contain only source and target IDs. Intrinsic eligibility rules (ownership, deletion/archive, dates, and bounds) still apply.

Saved target sessions remain on their saved dates. Previously suppressed missing sessions can be generated by normal preparation. No automatic account migration deletes goals, detaches links, transfers completion history, or consolidates monthly/yearly duplicates.

## Existing monthly-to-yearly links

Those goals may now receive additional independent target sessions. This is intentional: the relationship no longer represents a scheduling substitute. A single activity with varying monthly intensity should use one long-lived goal whose placements change over time. Consolidating existing goals requires a separate explicit migration decision.

## Separate future work: multiple sessions per day

The once-per-day assumption remains unchanged in this PR. It is enforced by completion and planner-item date uniqueness, the ordered solver, canonical goal/date completion operations, optimistic UI keys, and distinct-day cadence progress.

Stable planner unit keys, completion IDs, and reconciliation provide a useful base for session-addressed work. A future change should distinguish day-based habits from countable sessions/milestones and update storage, canonical complete/undo, cascade provenance, progress/rewards, allocation, and UI together. Dropping date uniqueness alone is insufficient.

The coach can eventually adjust the same annual goal's placements to monthly intent through canonical scheduling commands. Monthly child-goal substitution and a separate monthly commitment model are not part of this change.

## Coverage

Write regression coverage for independent target eligibility and placement across source deadlines and transitive links, preservation of saved target sessions, lack of projected source credit, actual cascaded completion credit, checklist visibility, and direct target navigation. Remove tests for deleted suppression APIs. No verification suites are run without the repository's explicit verification approval.
