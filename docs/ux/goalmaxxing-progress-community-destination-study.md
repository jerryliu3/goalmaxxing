# Progress and Community destination study

Status: **Progress Atlas/Pins ledger and Club compete layout are study locks
in the isolated worktree, not a production ship.** Ribbon is saved as an
idea, not the lock.

Clickable study: `/ux/destinations`

## Current take

Instrument (Ledger / Rhythm / Mix) is out. Destination tabs for Community
are out. The live prototypes assume **one page per destination**.

### Progress

The heatmap is not locked under a goal list on small screens. **Wide
screens** put a vertical goal list beside the map (the old ledger).
**Narrow screens** keep heatmap first, with a horizontal goal rail under it.

The **milestone runway** sits between the map and readings when Thesis is
focused. Thesis has **ten** stops so the runway can be judged at length.

**Atlas / Pins is locked** as the Progress design language: same responsive
ledger, same runway. Atlas uses quiet dots on milestone days; Pins numbers
the stops on the cell. Pick one mark style later; the page structure is
shared.

- **Ribbon** — saved. Weeks as ribbons, milestones as named stations. Not
  the lock.

### Community

**Team** is still its own component. Shared goals are a roster, not an editor —
tapping one is a Plan handoff, not a Community sheet.

**Compete** is two stacked carousels, not a side-by-side pair. **Club is locked:**

- Challenges: compact snap-tiles, joined first, you + Maya on the tile,
  ranks on click, Join / leave at the foot. Unjoined tiles are join-only.
- Boards: almost full-width posters you still snap between (stage size, next
  season peeks). No thumbnail rail. Same peek / join rules as challenges.

**Ranks** keeps that layout and opens the field on joined tiles. **Stage** is
still the thumbnail-rail alternative if we later prefer one featured season.
Presence remains the denser one-composition take.

Snap-scroll peeks the next tile. It does not loop.

## Out of scope

Production Progress/Community, `/ux/concepts`, and the Plan tab.
